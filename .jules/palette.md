## 2024-05-24 - Accessibility states for Native HTML5 `<dialog>` triggers
**Learning:** Native HTML5 `<dialog>` elements implicitly map to the `dialog` role. However, any custom trigger button used to open the dialog (e.g. a search icon) needs to explicitly declare `aria-haspopup="dialog"`, `aria-controls`, and dynamically manage `aria-expanded`. Because native dialogs can be closed via built-in methods (like the `Esc` key or programmatic `.close()`), relying strictly on click handlers to reset `aria-expanded` back to `false` creates desyncs for screen readers. The `close` event must be listened to on the `dialog` element itself to reliably reset trigger states.
**Action:** When working with `<dialog>`, always attach a `close` event listener to ensure associated trigger buttons have their `aria-expanded` state reliably reset to `false`, capturing both manual UI interactions and native dismissal methods.
