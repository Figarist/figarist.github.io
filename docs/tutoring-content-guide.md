# База контенту занять Figarist

Актуальний план і статуси: [центр документації](README.md).
Профіль, відгуки й умови вже заповнені; анкети нижче є інструкцією для нових
матеріалів. Схему та поведінку перевіряйте за `_plugins/tutoring_content.rb`
і відповідними include; старі приклади не перевизначають поточний код.

Цей документ описує дані, з яких сайт збирає публічні матеріали про заняття. Заповнюйте YAML-файли або відкривайте їх через Front Matter CMS. HTML, Ruby та SCSS для звичайного кейсу змінювати не потрібно.

> Цей файл навмисно виключений із `_site`. `noindex` і `sitemap: false` — додаткові запобіжники, але прихований у сайті файл усе одно може бути доступним у публічному Git-репозиторії. Не зберігайте тут чи в репозиторії документи про дозволи, реквізити, податкові номери або інші приватні матеріали.

## Карта змін

| Що хочу змінити | Де відкрити |
| --- | --- |
| Ціна, валюта, Telegram, BUKI, власна гра | `_data/tutoring/settings.yml` або Front Matter data file `Tutoring settings (shared facts)` |
| Один учнівський кейс | `_data/tutoring/cases/<стабільний-slug>.yml`; зразок — `_data/tutoring/cases/case-template.yml` |
| Готові порожні напрями | `_data/tutoring/cases/unity.yml`, `python.yml`, `scratch.yml` |
| Портрет і опис викладача | `_data/tutoring/profile.yml` або `Tutoring profile` |
| Відгуки | `_data/tutoring/testimonials.yml` або `Tutoring testimonials` |
| Переклад інтерфейсів, підписів і текстів напрямів | `_data/en/tutoring.json`, `_data/uk/tutoring.json`, `_data/ru/tutoring.json`, `_data/ko/tutoring.json` |
| Тексти labels полів | `_data/{lang}/strings.yml` — зазвичай уже готові |

Спільні факти не дублюйте в чотирьох мовних JSON: сума й валюта беруться зі `settings.yml`, URL — звідти ж, а мовна версія додає лише свій підпис.

## Рекомендований порядок першого заповнення

1. Фото й біографія: `profile.yml`, поля `portrait.path` та `translations.<мова>.short_description/long_description`.
2. Три кейси: `cases/unity.yml`, `cases/python.yml`, `cases/scratch.yml`; спершу залиште `status: draft`, `permission: false`.
3. Два–три реальні відгуки: `testimonials.yml`, список `items`, точний текст або посилання та дозволений підпис.
4. Тривалість і умови: `settings.yml`, `conditions.duration` та інші підтверджені поля. Невідомі залиште `null`.
5. Готовність кожного перекладу перевіряйте окремо через `ready: true`.

## Учнівський кейс: що означає кожне поле

Відкрийте `case-template.yml` і скопіюйте його під новим стабільним ім’ям. Не перейменовуйте `id` або `slug` після публікації без окремої причини.

| Поле | Обов’язковість | Де видно |
| --- | --- | --- |
| `id` | Обов’язкове для публікації | Внутрішній ідентифікатор; не показується як текст |
| `slug` | Обов’язкове для публікації | Внутрішній ключ запису; окремий маршрут кейсу не створюється |
| `direction` | `unity`, `python`, `scratch`, `informatics` або `minecraft`; обов’язкове для публікації | Відповідна сторінка напряму |
| `order` | Обов’язкове для публікації | Порядок на головній і в напрямі |
| `featured` | Необов’язкове, за замовчуванням `false` | Якщо `true`, кейс може з’явитися серед обраних на головній |
| `status` | Для нового запису залиште `draft` | `draft` не потрапляє в жоден публічний блок |
| `permission` | Має бути `true` перед публікацією | Не показується; це контроль власника |
| `student_name` | Необов’язкове | Підпис кейсу, якщо учасник дозволив ім’я; порожнє значення означає анонімний кейс |
| `age_or_grade` | Необов’язкове | Вік або клас, лише якщо це дозволено до публікації |
| `duration` | Необов’язкове | Фактична тривалість саме цієї роботи; не стає обіцянкою для інших учнів |
| `media.cover.path` | Необов’язкове | Обкладинка картки; локальний файл має існувати |
| `media.additional_images` | Необов’язкове | Додаткові матеріали; кожен локальний файл потребує alt для готової мови |
| `media.video_url` | Необов’язкове | Посилання на відео, якщо його справді можна показати |
| `media.playable_url` | Необов’язкове | Посилання на версію, яку можна запустити |

У кожному `translations.<мова>`:

- `ready` — дозвіл опублікувати саме цей переклад. Не ставте `true`, поки весь блок не перевірено.
- `title` — назва проєкту.
- `card_description` — короткий чесний опис для картки.
- `full_description` — докладніший контекст без тонкої SEO-сторінки.
- `starting_level` — що учень знав на початку.
- `goal` — чого хотів досягти.
- `created` — що саме створено.
- `student_work` — що учень зробив самостійно.
- `tutor_help` — у чому допоміг викладач.
- `skills` — конкретні опановані навички; готова гра сама по собі не доводить володіння всіма навичками.
- `evidence` — як результат можна перевірити: робоча функція, код, демонстрація, посилання тощо.
- `cover_alt` — обов’язковий опис обкладинки, якщо `media.cover.path` заповнений.

Для публікації достатньо однієї готової мови. Наприклад, UK-кейс із `uk.ready: true` буде видно лише в українській версії. Порожні або частково перекладені EN/RU/KO не показуються й не створюють посилань на 404.

Дозволений підпис або анонімно:

## Профіль викладача

У `profile.yml`:

- `status: draft` залишайте, доки опис і публічні докази не перевірені.
- `portrait.path` — шлях до справжнього локального фото. `portrait.aspect_ratio` підтримує `4 / 5` (за замовчуванням), `1 / 1` і `3 / 2`; `object_position` підтримує `top`, `center` або `bottom`. Якщо фото немає, залиште `path: null`.
- У мовному блоці заповніть `short_description`, `long_description` і `portrait_alt`, якщо фото є. Окремий переклад має власний `ready`.
- `verified_facts.experience`, `education`, `certifications` — списки фактів. Для кожного публічного факту вкажіть назву, за можливості дату й публічний URL підтвердження, а `status` перемкніть на `published` лише після перевірки.

Профіль уже містить освіту, Unity Junior Programmer, Unity Essentials та нагороду.
Список experience порожній: числовий стаж не можна домислювати. Назви бейджів
не замінюйте на «Unity Certified Developer». Особисті документи не зберігайте в Git.

## Відгуки

У `testimonials.yml` додайте об’єкт до `items`:

- `id` — стабільний ключ.
- `mode: exact_text` — покажемо точний наданий текст без перефразування; заповніть `text`.
- `mode: source_only` — схема має такий режим, але поточна карусель не має окремої
  гілки його відображення. Перед новим source-only записом перевірте шаблон;
  не обіцяйте автоматичну картку з поясненням, якої в ньому немає.
- `language` — мова оригіналу: `uk`, `en`, `ru` або `ko`. Поточний компонент
  показує опубліковані записи на мовних сторінках із відповідним атрибутом `lang`;
  не вважайте це автоматичним перекладом або фільтром за мовою сторінки.
- `signature` — дозволений спосіб підпису; ім’я не обов’язкове.
- `permission: true` — підтвердження дозволу, коли воно потрібне.
- `ready: true` і `status: published` — обидва потрібні для публікації.
- `date` і `direction` — необов’язкові факти.

Якщо опублікованих записів немає, секція не рендериться. Зараз записи вже є;
компонент показує наявний rating, джерело й точний текст. Не додавайте вигадані
оцінки. У settings.yml збережено окремі знімки: 11 відгуків BUKI та 7 Асоціації.

## Умови занять

`settings.yml` — єдине місце для підтверджених умов:

- `format: online` — формат занять.
- `price.amount: 1000` і `price.currency: UAH` — спільна ціна.
- `payment.account_type: FOP` — підтверджений тип оплати; валюти й еквіваленти
  не додавайте за старими прикладами, використовуйте лише актуальні дані.
- `contact.telegram_url` — особистий Telegram для запису.
- Формулювання про мови викладання перевіряйте в актуальних локалізованих
  даних; не додавайте відсутнє поле за старим прикладом.

Поля умов уже заповнені: 60 хвилин, платне перше заняття, Zoom та інші правила
в settings.yml. Зберігайте їх зміст під час редагування дизайну. Зміна політик
потребує рішення автора. Порожнє необов'язкове поле не виводиться.

## Медіа: формат і структура

Зберігайте локальні зображення в `assets/images/tutoring/` або іншій передбачуваній підтеці `assets/images/`, наприклад `assets/images/tutoring/case-slug/cover.webp`. Для обкладинки використовуйте приблизне співвідношення 8:5, для додаткових зображень — достатню ширину для перегляду на телефоні; сайт резервує місце через `width` і `height`. WebP — бажаний формат для нових зображень. Для першого кейсу достатньо однієї обкладинки або навіть тексту без медіа — професійне відео не потрібне.

Не використовуйте випадкові стокові фото як доказ роботи учня. Переконайтеся, що маєте право показувати кожне зображення, і додайте змістовний alt. `Jekyll exclude` прибирає файли зі збірки, але не робить їх приватними в публічному GitHub-репозиторії.

## Preview, build і статус публікації

1. Заповніть запис, але залиште `status: draft`, `permission: false`, `ready: false`.
2. Перевірте локально `bundle exec jekyll build`. Якщо published-запис неповний, збірка покаже точний файл і поле та завершиться помилкою.
3. Запустіть `bundle exec jekyll serve --skip-initial-build --host 127.0.0.1 --port 4000` і відкрийте відповідну мовну сторінку напряму.
4. Перевірте, що текст, зображення, alt, URL і мова справді правильні; draft не має бути в HTML, `search.json`, sitemap або JSON-LD.
5. Після перевірки поставте `permission: true`, заповніть потрібний переклад і лише тоді `ready: true` та `status: published`.
6. Знову зберіть сайт і перевірте сторінку. `published` у data-файлі не означає автоматичного деплою в інтернет: для цього потрібен окремий дозволений процес публікації репозиторію.

## Типові помилки

| Помилка | Як виправити |
| --- | --- |
| Кейс не видно | Перевірте `status`, `permission`, `translations.<мова>.ready` і всі обов’язкові поля. |
| Білд каже `local file does not exist` | Виправте шлях `media.cover.path` або додаткового зображення від кореня репозиторію; файл має бути в Git. |
| Білд каже, що немає `cover_alt` | Додайте alt у готову мовну версію, не залишайте його порожнім. |
| На одній мові є текст, на іншій порожньо | `ready: true` ставте лише для готової мови; не копіюйте український текст як переклад. |
| З’явилося зайве поле умов | Перевірте, чи поле не містить вигадану відповідь; `null` прибирає його з публічного тексту. |
| Портрет займає порожній простір | Залиште `portrait.path: null`; компонент не рендерить рамку без фото. |
| Відгук змінює зміст | Використовуйте `exact_text` лише для точного тексту; для джерела без копіювання — `source_only`. |

Тестовий запис для QA зберігається лише у виключених fixtures і не є реальним кейсом. Не копіюйте його в `cases/` і не залишайте тестові медіа у фінальному `_site`.
